# Monitoring and alerts

Everything is self-hosted and free (docs/08). Two alert paths, both ending in one private
Telegram chat:

| Path | What | Where |
|---|---|---|
| **On-chain** (ADR-014) | Every role grant/revoke, upgrade, pause/unpause, timelock schedule/cancel/execute, parameter change, recipient/feed/split changes, Market Open, MOHN minted beyond accrued emission (critical), mints and transfers ≥ 50,000 MOHN | The indexer raises them from the events it already reads (`services/indexer/src/alerts`) into the `alerts` outbox, and its notifier sends them (Telegram, optional webhook). No extra RPC calls. |
| **Service health** | Indexer down/stalled/lagging, alerts stuck, RPC budget; keeper down, no lock holder, balance < 0.002 ETH, failing tasks, poke stale, price-guard skips; API down, 5xx ratio, p95 latency | Prometheus rules (`prometheus/rules/mohonaut.yml`) → Alertmanager → Telegram |

OpenZeppelin Monitor was the original plan (docs/06 3.4). It processes the chain block by block,
and Robinhood Chain makes ~864,000 blocks a day, which a free RPC tier cannot serve; our indexer
already reads exactly the events we alert on (ADR-014).

## Stack (`docker-compose.yml`)

Prometheus (30 days), Alertmanager, Grafana (dashboards: indexer, keeper, API — generated by
`tools/gen_dashboards.py`), Loki + Grafana Alloy (container logs), Uptime Kuma (public status
page). All listen on 127.0.0.1 only; Grafana and the status page are published through
Cloudflare (Access in front of Grafana) in Phase 6.

```bash
# on the server, once: secrets outside the repository, readable by root only
sudo install -d -m 700 /etc/mohonaut/secrets
sudo sh -c 'umask 077; cat > /etc/mohonaut/secrets/telegram_bot_token'      # paste, Ctrl+D
sudo sh -c 'umask 077; openssl rand -base64 24 > /etc/mohonaut/secrets/grafana_admin_password'
# set the alert chat id in alertmanager/alertmanager.yml (chat_id), then
cd infra/monitoring && docker compose up -d
```

The indexer uses the same bot: `ALERT_TELEGRAM_TOKEN_FILE=/etc/mohonaut/secrets/telegram_bot_token`
and `ALERT_TELEGRAM_CHAT_ID=<chat id>` (services/indexer/README.md).

**Uptime Kuma** (configured in its UI at http://127.0.0.1:3001 through an SSH tunnel): HTTP
monitors for the website, `api…/healthz`, and the RPC endpoint; keyword monitor for
`/world`; a status page at `/status/mohonaut` with those monitors. Its own notifications go to the
same Telegram bot.

## Proof that alerts fire

- Alert rules: `promtool test rules prometheus/tests/mohonaut_test.yml` feeds synthetic series and
  checks which alerts fire and when (CI job `monitoring`, also validating every config file).
- On-chain rules: `services/indexer/test/alerts.test.ts` replays a fixed history (timelock
  change, Market Open, parameter change) and a forged over-emission mint, and delivers through a
  fake Telegram server (retry, skip of stale alerts).
- Live: the next testnet deployment emits dozens of role events within minutes; with the bot
  configured they must arrive in the chat (checklist in docs/KURUCU_YAPILACAKLAR.md).
